<objective>
Make the tutor's tool contract exist exactly once. Today the same 21 tools are
declared three times with hand-synchronised descriptions and schemas — in
`server/src/agent.ts`, in `server/src/mcp.ts`, and implicitly in the
`server/src/index.ts` action switch — and CONCERNS.md records the two prompts
already drifting. Per D-05 one registry in `server/src/tools.ts` becomes the
source for all of them, and per D-08 a committed wire-surface fixture makes any
change to what the model reads show up as a reviewable diff.

This plan leads with a tracer: **one** tool, `node_status`, taken from the new
registry through every contract layer at once (D-05, D-06, D-08) before the
other twenty ride on the same shape. `node_status` is the right tracer because
`server/test/api.test.ts` already drives it hard — it is the tool that locks
nodes, refuses a procedure-only lock, and returns the cumulative-quiz
instructions — so the existing suite is the net under the tracer from the first
commit.

Purpose: FOUND-01 and the machine half of FOUND-04. Every later phase (the owned
loop, per-provider schema projection, local-model description compaction) reads
this registry.
Output: a 21-entry registry, two consumers driven by it, and a snapshot fixture
that fails CI on drift.
</objective>

| Boundary | Description |
|----------|-------------|
| model -> HTTP action route | the tutor model (in any terminal) supplies the JSON body of `POST /api/external/lessons/:id/:action`; today it is `as`-cast, not validated |
| model -> in-process tools | the Claude Agent SDK passes model-authored arguments into `server/src/actions.ts` |
| repo -> committed fixture | `server/test/wire-surface.json` is what a reviewer trusts to describe the wire surface |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-01 | Tampering | `POST /api/external/lessons/:id/node_status` body | medium | mitigate | D-06 `safeParse` against the registry shape before any method logic; unknown `status` values are rejected 400 instead of being written into `nodes.status` |
| T-01-02 | Tampering | `server/test/wire-surface.json` | medium | mitigate | the fixture is regenerated from the registry in the test, so a hand-edited fixture that does not match the code fails; a code change that moves the surface fails until the fixture is regenerated and reviewed |
| T-01-03 | Information disclosure | tool descriptions in the snapshot | low | accept | descriptions are the teaching method's model-facing text; they contain no secret and D-08 deliberately stores them in full so the diff is readable |
| T-01-04 | Denial of service | zod parse of a large action body | low | accept | the body is already read whole by Hono before this plan; parsing cost is bounded by the existing body size and unchanged by adding validation |
| T-01-05 | Repudiation | a silent contract change | medium | mitigate | any change to a name, description or schema fails `server/test/wire-surface.test.ts` and must appear as a fixture diff in the pull request |
| T-01-SC | Tampering | npm/pip/cargo installs | high | mitigate | this plan adds no dependency; `server/package.json`, `package.json` and `pnpm-lock.yaml` are not modified. A package-legitimacy audit is therefore not required here — if execution finds it needs a new package, stop and raise it rather than installing |
</threat_model>
