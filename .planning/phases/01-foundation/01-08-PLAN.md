<objective>
Make sure nothing leaks, and close the three ways the server can be pointed at
things it should not read — while the phase is still quiet, before Phase 2 puts
provider keys in this process.

Per D-11 one `redact()` chokepoint covers every egress, with exact-match
replacement everywhere and a key-shaped-pattern backstop confined to errors and
logs. That confinement is deliberate and is the interesting part: Derive teaches
anything, including API security, so a lesson whose prose legitimately contains
a key-shaped example must reach the learner's Obsidian vault unharmed.

Per D-10 the SSRF and path-read fixes ride along beyond FOUND-06's literal
wording, because the tutor model itself can call `add_resource` with any URL,
Phase 3 gives it web fetch on every provider, and Phase 2 is when keys land. This
is the last quiet moment to close it.

Then the phase's first success criterion gets its human half: a real lesson
through the plugin and a real lesson through Codex, run after everything has
landed.

Purpose: FOUND-06's redaction half, the D-10 ride-alongs, and the human half of
FOUND-04.
Output: one secrets module, guards on two fetch paths and one ingest path, and a
signed-off parity run.
</objective>

`registerSecret(value)` adds a value, ignoring anything empty, whitespace-only, or shorter than a documented minimum length — pick a minimum in the region of sixteen characters and say in the doc line why: a short or blank registered value would turn redaction into a text shredder that mangles ordinary lesson prose. `redact(text)` replaces every exact occurrence of every registered secret with a fixed marker, applying the longest registered value first so no fragment of a longer secret survives a shorter overlapping one. With nothing registered it returns the input unchanged, and it should short-circuit on an empty set, because it will run on every emitted event. `redactErrors(text)` is `redact` plus the key-shaped pattern backstop — the prefixes D-11 names and a bearer-token form — and it is the only function that does pattern matching.

Add `redactDeep(value)` beside them: a structural walk that applies `redact` to every string inside a JSON-serialisable value and leaves everything else alone, since event payloads are objects rather than strings.

Wire the exact-match chokepoint. In `server/src/events.ts`, run `redactDeep` on the payload in `emit`, `emitUpdate` and `emitEphemeral` before it is persisted or fanned out, so the database, the SSE stream and every subscriber see the redacted form and there is no window where an unredacted payload exists downstream. Do not run the pattern backstop here. In `server/src/export.ts`, run `redact` on the rendered Markdown in `renderMarkdown` before it is returned, which covers `exportToVault` and the debounced `mirrorToVault` in one place. Again exact match only: this is the learner's durable record.

Wire the backstop. In `server/src/index.ts`, wrap the message in every catch that builds an `{ error }` body with `redactErrors`, keeping the existing `e instanceof Error ? e.message : String(e)` narrowing exactly as it reads, and wrap the message in the `[tag]`-prefixed console lines the same way. Register the install token at boot: call `registerSecret` on it immediately after `ensureToken()` returns, before any route is registered, so no request can be served before the value is protected.

In `server/src/library.ts`, add an `assertPublicHost(url)` guard that resolves the URL's hostname with `node:dns/promises` and refuses when any resolved address is loopback, link-local (including the cloud metadata address), RFC-1918 private, carrier-grade NAT, unique-local IPv6, or the unspecified range — and that checks a literal IP host directly without a lookup. Refuse with a lowercase sentence in the file's existing style, of the same register as its `larger than 6 MB` message, naming that the address is a private or local one. Keep the existing http/https scheme restriction in `normalizeUrl` and make it explicit rather than incidental.

Apply the guard in `get()`, the single function every library fetch routes through, and re-apply it on every redirect hop. That means replacing the follow-redirects mode with a manual loop: call the guard, fetch without following, and when the response is a redirect resolve the location against the current URL, bound the hop count to a small number, and go round again. Keep the existing timeout, the existing size caps and the existing accept headers exactly as they are, and keep returning the final URL as the function already does, since callers rely on it.

In `server/src/repo.ts`, add `isSecretName(path)` covering the names D-10 lists — `credentials`, any `.pem` or `.key` extension, any basename beginning with `id_`, `.netrc`, `.npmrc`, `auth.json`, and any basename beginning with `.env`. Add it as a further conjunct to the existing filter in `fromDirectory`, and apply it in `walk` as well so a matching file is never even collected. In `fromDirectory`, refuse a root that resolves to the filesystem root or to the user's home directory outright, with a lowercase sentence saying to name the project folder instead — a repository import of an entire home directory is never what the learner meant.

In `fromGitClone`, check the URL's scheme before the git binary is invoked and refuse anything that is not `https://`, so a `git@` or `ssh://` URL can never reach the learner's SSH keys. The check must precede the process spawn, not sit inside a try around it.

In `fromGitHub`, add a timeout to the tarball fetch in the style of the library fetcher, and a size cap: reject on a declared content length above the cap before buffering, and bound the buffered read so a server that declares nothing cannot grow the buffer without limit. The decompression that follows happens in memory, so the cap is what protects it.

Extend `server/test/secrets.test.ts` or add a sibling test file, whichever reads better. Cases: `normalizeUrl` refuses a non-http scheme; the host guard refuses a loopback hostname, a literal loopback IP, an RFC-1918 literal and the metadata address, and accepts an ordinary public literal; `fromGitClone` refuses an `ssh://` and a `git@` URL with no process spawned; `fromDirectory` refuses `/` and `~`; a directory containing a file named `credentials`, one named `id_rsa`, one named `.env` and one ordinary text file yields only the ordinary file. Drive the guards directly rather than over the network so the suite stays offline.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| model-supplied URL -> outbound fetch | the tutor can call `add_resource` with any URL, and Phase 3 gives it web fetch on every provider |
| learner-supplied path -> filesystem walk | `POST /api/materials/repo` walks a directory and stores its text where the model can read it |
| secret values -> every egress | errors, logs, events, the SSE stream, the Markdown export and the Obsidian vault mirror |
| redaction -> lesson content | over-broad redaction damages the learner's durable record, which is its own failure |
