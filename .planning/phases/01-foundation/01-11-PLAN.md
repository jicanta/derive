<objective>
Make the two delete functions do what their own comments promise.

Migrations 2 and 3 added the `turns` and `usage` tables. `deleteLesson` deletes
from materials, memory, misconceptions, quiz results, nodes, events and lessons —
and nothing else. Its doc comment says "Removes a lesson and everything hanging
off it"; `deleteLearner`'s says "Removes the learner and everything they
learned". Both are now false, which is review finding WR-01.

For a local-first product whose promise is that the learner owns their record,
a deleted learner's per-request token counts, model ids and driver names
surviving the deletion is a data-deletion defect, not untidiness. The tables
also grow without bound.

Purpose: WR-01, the honest half of COST-01's ledger and FOUND-05's transactional
deletes.
Output: four prepared statements, two corrected comments, and cases that count
rows rather than assert that nothing threw.
</objective>

## Artifacts this phase produces

`server/src/db.ts` — `deleteUsageByLesson`, `deleteTurnsByLesson`,
`deleteUsageOfLearner`, `deleteTurnsOfLearner`. No new exported function, no new

`server/test/tx.test.ts`, the existing `lessonWithHistory` helper gains a turn
and a usage row, and a new `describe('the usage ledger')` block is added.

## Why this plan is wave 3 and not wave 1

Its task 2 runs the whole-tree gate — `pnpm build` then `pnpm test` — and that
gate is not scoped to this plan's files: it compiles the whole workspace into the
shared `server/dist` and `web/dist` and then spawns the built server. Plans 01-09
and 01-10 run the same gate. Two plans running it at once do not merely race over
the build directory, they each observe a tree carrying the other's half-finished
edits, so neither result means what it says. The edge is therefore declared
rather than justified: this plan waits for 01-10, which waits for 01-09. Nothing
in `server/src/db.ts` or `server/test/tx.test.ts` depends on either of them —
this is a gate ordering, not a code dependency.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| learner-requested deletion -> the stored record | `DELETE /api/learners/:id` and `DELETE /api/lessons/:id` are the learner asking Derive to forget something |
| a deleted learner's usage rows -> a later reader | model ids, driver names and token counts outliving the learner they describe are data the learner asked to be rid of |
| unbounded table growth -> a local SQLite file | `turns` and `usage` accumulate one row per model request with nothing ever removing them |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-11-01 | Information disclosure | a removed learner's model ids, driver names and token counts surviving in `usage` and `turns` (WR-01) | medium | mitigate | learner-scoped deletes of both tables inside `deleteLearner`'s existing transaction, asserted by a whole-table count after the delete |
| T-11-02 | Repudiation | doc comments promising complete deletion that the code does not perform | medium | mitigate | both comments rewritten to list the tables they clear; the acceptance criteria check the table names are named |
| T-11-03 | Tampering | a delete scoped to one lesson reaching another lesson's rows | high | mitigate | every statement filters on `lesson_id` or `learner_id` with a bound parameter and no string interpolation; an adjacency case asserts a sibling lesson's counts are unchanged |
| T-11-04 | Tampering | a partial delete leaving a usage row pointing at a removed turn | medium | mitigate | both deletes run inside the `withTx` the functions already open, usage before turns; the existing RAISE-trigger failure cases are extended to cover the two new tables |
| T-11-05 | Denial of service | unbounded growth of `turns` and `usage` on a long-lived install | low | mitigate | deletion now reclaims them; no sweep or retention policy is added, which would be a product decision rather than a gap fix |
| T-11-06 | Tampering | a well-meant backfill or cleanup destroying rows the learner did not ask to remove | high | mitigate | explicitly prohibited: this plan adds no migration, no sweep and no backfill, and `PRAGMA user_version` stays at 3 — asserted in the acceptance criteria |
| T-11-SC | Tampering | npm/pip/cargo installs | high | mitigate | this plan adds no dependency; it is four SQL statements and test cases on the built-in `node:sqlite` and `node:test`. If execution finds it needs a package, stop and raise it rather than installing |
</threat_model>
