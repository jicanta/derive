<objective>
**As a** learner who hands Derive a repository to teach from, **I want to** know that the import reads only the repository I named, **so that** a link inside it — planted by a hostile repo, or chosen by a prompt-injected model — cannot read my install token, my ssh key or anything else on this machine into course material and send it to the model.

This is the closure the verification report named for the token disclosure it
reproduced. `walk()` and `fromDirectory`'s read loop resolve every entry with
`statSync`/`readFileSync`, both of which follow symlinks, and `isSecretName`
judges the repo-relative name — so a link called anything ordinary reads its
target from anywhere on disk. The verifier imported a folder holding
`notes.md -> DATA_DIR/token` and read the 64-hex install token back out of
`GET /api/materials/:id?text=1`.

Redaction is not the fix and must not be reached for: `materialEvent`
(`server/src/index.ts:475`) carries metadata only, so material text never
passes the `emit` chokepoint, and D-11 keeps pattern redaction off lesson
content on purpose. The refusal in the importer is the real closure.

Two smaller items on the same premise ride along, because they are the same
file and the same guarantee: the tarball path does not run `isSecretName`
though the guard's own doc comment says it does, and `fromGitClone` runs
`assertPublicHost` on the URL the caller supplied while git's documented
`http.followRedirects` default is `initial` — which follows exactly the one hop
the guard judged.

Purpose: Success Criterion 5's "no secret appears in any … event, export"
half, at the one path the redaction chokepoint cannot reach.
Output: an importer that cannot read outside the tree it was given, one filter
that is true of both import shapes, a clone pinned to the judged URL, and
cases that drive each of them.
</objective>

| a repository's contents -> the importer's filesystem reads | a repo is attacker-controlled data; a symlink inside it is an instruction to read somewhere else |
| the tutor model -> `attach_material` | the model chooses the repo URL, and a prompt-injected model chooses a hostile one; this is a remote path needing no local access |
| course material -> the model and the learner's Obsidian vault | material text bypasses the `emit` redaction chokepoint by design (`materialEvent` carries metadata only), so whatever the importer reads leaves the machine |
| the URL `assertPublicHost` judged -> the URL `git` actually fetches | a public URL is free to redirect to a private address, and git's default follows the initial hop |
