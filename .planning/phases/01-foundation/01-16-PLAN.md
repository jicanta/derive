**As a learner** who cloned this repo and ran `pnpm test`, **I want to** see it
pass on the first try, **so that** a red run means something is broken rather
than that two test files picked the same port.

`01-REVIEW.md` IN-05 and the re-verification both recorded the same thing: the
first `pnpm test` exited 1 with six cancelled subtests, and an identical second
invocation passed 159/159. `server/test/api.test.ts:53`,
`server/test/security.test.ts:93` and `server/test/security.test.ts:258` each
pick a port by arithmetic on a random number with no retry, and
`server/test/mcp.test.ts:83` does the same. Node's test runner runs files
concurrently, so a clash makes the child exit, the health loop burns its whole
twenty-second deadline, and the throw reads `server did not start` — a product
failure by appearance and a port collision in fact.

That is not a cosmetic problem for this phase. FOUND-04's machine half *is* the
suite: the wire-surface snapshot and the modelless stdio smoke test are the only
automated evidence that the Claude Code plugin and the Codex skills still work,
and a gate that fails one run in N is a gate nobody trusts. It is also why this
plan runs first: every gap plan after it proves a security fix with `pnpm test`,
and until this lands a red run cannot be read.

Riding with it, because it is the same subject and the same file, is
`01-REVIEW.md` IN-06: `server/src/config.ts:8` accepts any `PORT` at all. With
`PORT=abc`, `String(PORT)` is `NaN`, so `guardLocal`'s port comparison at
`server/src/index.ts:206` is false for every request and the server binds
somewhere and then refuses everything 403. That is the loudest possible failure
made silent, on the check D-12 put there.

Purpose: FOUND-04's proof net is only proof if it is deterministic, and D-12's
Host-and-port check is only a guard if the port it compares against is a port.

Create `server/test/spawn.ts`. It is deliberately not named `*.test.ts`: the runner's glob in `server/package.json` is `test/*.test.ts`, so this file is imported by suites and never executed as one. Open it with a `/** … */` prose module block in the register the rest of the repo uses — what the module is for and why it exists — naming the finding it closes (`01-REVIEW.md` IN-05: three files picking a port with no retry, under a runner that executes files concurrently) and the reason the retry is bounded rather than infinite.

Export three things, named exports only, no default:

- `SPAWN_ATTEMPTS` — the retry ceiling, `5`.
- `freePort(): Promise<number>` — create a `node:net` server, `listen(0, '127.0.0.1')`, read `address()` as a `net.AddressInfo` and take its `port`, `close()`, resolve the number. The operating system is the allocator; nothing here invents a range. One `//` line says why this is not the same as picking a number: the OS will not hand the same ephemeral port to two listeners that are up at the same time, and the window between `close()` and the child's own `listen` is microseconds rather than the whole test run.
- `startDeriveServer(entry: string, env: Record<string, string> = {}, opts: { dataDir?: string; deadlineMs?: number; attempts?: number } = {}): Promise<{ child: ChildProcess; port: number; base: string; dataDir: string }>` — the one spawn path. Per attempt: take `opts.dataDir` or make one with `mkdtempSync(join(tmpdir(), 'derive-server-'))`; take a port from `freePort()`; spawn `process.execPath` with `[entry]` and env `{ ...process.env, PORT: String(port), DERIVE_DATA_DIR: dir, DERIVE_BACKEND: 'claude', ...env }`, `stdio: ['ignore', 'pipe', 'pipe']`; accumulate the child's stderr into a string with a `data` listener so a real failure has a sentence to report; register `child.once('exit', …)` setting a flag; then poll `GET http://127.0.0.1:<port>/api/health` every 200 ms against `opts.deadlineMs ?? 10_000`, returning `{ child, port, base, dataDir }` on the first `res.ok`. Break out of the poll the moment the exit flag is set rather than waiting out the deadline — that is the second half of the fix, because IN-05's twenty seconds are spent on a child that is already gone. On a failed attempt, `child.kill()`, and if the data directory was made here remove it before the next attempt so a half-initialised one is never reused. After `opts.attempts ?? SPAWN_ATTEMPTS` failures throw a plain `Error` with a lowercase sentence in the project's register, carrying the attempt count and the last non-empty line of the child's stderr — for example `the derive server did not start in 5 attempts: <last stderr line>`. Never swallow that: a server that genuinely cannot start must still fail the suite, which is the prohibition this plan carries.

Note in a `//` line inside `startDeriveServer` why the port is taken from `freePort()` and passed in rather than letting the child bind an ephemeral port itself: `guardLocal` at `server/src/index.ts:206` compares the Host header's port against `String(PORT)`, the configured value, so a port the child chose for itself would make every request 403. That is the same coupling Task 3 validates.
