<objective>
**As a learner** on a machine I share with other accounts, **I want to** know
that starting a lesson does not publish my install token to every process on
the box, **so that** "keys stay local" means local to me and not merely local
to the machine.

Three things are left on the front door, and they are the same subject: what
the browser is handed, how long it holds it, and what the project says about
both.

`server/src/mcp.ts:191-206` builds `http://localhost:4310/lesson/<id>?token=<the
install token>` and hands it to a call that spawns `/bin/sh -c` and then the
browser. The token lands in two process command lines, and on Linux
`/proc/<pid>/cmdline` is world-readable, so any other local account can read it
with `ps` for as long as that browser runs. That defeats the property the rest
of the code treats as load-bearing: the token file is written 0600,
`scripts/doctor.mjs` **fails** if the mode is anything else, and `registerSecret`
plus `safeMessage` scrub the token out of every error body and log line. This
path routes around all of it.

`server/src/index.ts:150-152` returns the loopback name set when the
connection's local address is unavailable and calls that "fail closed to
loopback". The set it returns admits `localhost`, `127.0.0.1`, `::1` and
`[::1]` — the forged loopback `Host` the check exists to refuse on a widened
bind (**D-12**). Failing closed would be an empty set. Plan `01-14`'s own truth
asserts the opposite of what the line does.

And the `derive_session` cookie carries no `Max-Age` and no `Expires`, so it
dies with the browser — while `README.md`, `.env.example`, `scripts/doctor.mjs`
and the startup line all say "once per browser". Because the handoff link is
only printed when the server starts, a learner who closes their browser on a
long-running server has no printed link to return to. HC-1 asks a human to
confirm they have a usable way back in.

Purpose: **FOUND-06** — the per-install token, the `Host` check and the
sentences about them — closed on the last three things the verifier found open.
Output: a single-use handoff ticket, a shell-free browser open, a fail-closed
`hostNames`, a cookie with a stated lifetime and a revocation story, and four
learner-facing sentences that are true.

## Two decisions taken here, with the reasoning

**The ticket is not a second token, and it does not violate D-09.** D-09's
binding commitment is that no endpoint ever hands the install token out, and
`01-09`'s supersession note strengthened it: the token now never leaves the
server process at all, and the browser is handed a *derived* credential
instead. A handoff ticket is the same shape one step further — a random value
with a sixty-second life and a single use, minted only for a caller that has
already proved it holds the token, and not reversible to it. The token still
never leaves the process. What changes is only what the MCP server puts on a
command line.

**The cookie gets a bounded lifetime rather than the sentences getting
narrower.** Two repairs were available for the "once per browser" gap: say
"once per browser session" in four places, or make the sentence true. The first
leaves a learner on a long-running server with no way back except reading a
0600 file out of their data directory mid-lesson — a live cost against the
binding one-screen-one-next-step rule, and the same complaint `01-REVIEW.md`
WR-02 makes. The second is a security decision, so it is recorded here and in
the threat model rather than only in a documentation edit: a thirty-day
`Max-Age` on a cookie that is `HttpOnly`, `SameSite=Strict`, `Path=/`, issued
only on a response that already passed the `Host` and `Origin` checks, over a
loopback-only bind by default. It is revocable without a code change, because
its value is `HMAC-SHA256(token, "derive browser session v1")` — rotating or
deleting `~/.derive/token` invalidates every cookie ever issued. Thirty days is
long enough that a learner returning after a holiday is not locked out, and
short enough that an abandoned browser profile does not carry a working
credential indefinitely.
