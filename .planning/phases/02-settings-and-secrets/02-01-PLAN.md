## Phase Goal

**As a** learner, **I want to** choose the provider and model that teach me inside the app, see what my machine already offers, store keys safely and test the connection, **so that** I always know which model is teaching me and nothing about the method changes when I switch.

(The ROADMAP `**Goal:**` line for Phase 2 is prose-form; the story above restates it without adding anything.)

## Acceptance Criteria (phase, from ROADMAP success criteria)

- [ ] SC1 — pick a provider and a model, restart, same choice active (this plan over HTTP; plan 06 on the page)
- [ ] SC2 — key pasted once, masked, 0600 file, never echoed (plan 02)
- [ ] SC3 — logged-in CLIs, env keys as "set from environment", local servers on default ports (plan 06: logins and ports; plan 02: environment)
- [ ] SC4 — fetch models or type an id, curated default preselected (plan 03)
- [ ] SC5 — test connection with the provider's own failure sentence; provider · model in the header and the plugin start message (plan 03, plan 04)

Signal: the boot-time `backend()` memo (one backend, decided once, derived from env or login) becomes a chosen, per-turn `TutorChoice` (provider and model, resolved from env, then the settings table, then detection), with an optional per-learner model override arriving in plan 05.
Noun now primary: `TutorChoice` from `resolveTutor()` in `server/src/settings.ts`.
Decision: **promote**. `backend()` and `backendSource()` are deleted and every call site (`agent.ts` `runTurn`, `/api/health`, `/api/stats`, the startup line) reads the new module. Two resolver modes exist because the callers differ: `resolveTutor()` for a turn (may run the login detectors when its memo is stale) and `currentTutor()` for read-only routes (reports the last pass, never spawns). Rationale: two sources of truth for "which backend" drift the first time one is edited; the `Backend` type survives only as the dialect the two login drivers and `systemPrompt()` speak, produced by `backendOf(provider)`.
Invariant test encoding the intent: `settings.test.ts` "a change made through POST /api/settings/active is what the very next turn runs on, with no restart" plus a source assertion that the memo variable is gone from `backend.ts` and a marker-file assertion that read-only routes spawn nothing.
