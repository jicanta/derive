# Plan 02-07 — Close the Phase 2 UAT and UI-review gaps

defect against a contract already agreed in `02-UI-SPEC.md` or an expectation already written into
`02-UAT.md` — nothing here is a new feature, and nothing changes what the tutor does. The owner
reviewed all six findings and asked for them closed before the phase is marked complete.

No new colour tokens, no new components, no new copy beyond the one hint sentence that now names
the wrong mechanism. Trim, do not add.

<tasks>

<task id="1" name="Apply the seven fixes">

**1. `web/src/pages/Settings.tsx:102` — title overflows the header below `md`.**

The `<h1>` has no `truncate`, so on a 375px viewport `Settings · which model teaches` wraps to two
lines and fills the whole 60px header, touching the top edge and the hairline. `Lesson.tsx:115`
already solves this. Add `truncate min-w-0` to the `<h1>` class list, leaving everything else
as it is.

**2. `web/src/pages/You.tsx:84` — the same defect, the same fix.**

`How you learn · read by the tutor before every lesson` is longer than the Settings title, so it
wraps too. Add `truncate min-w-0`.

**3. `web/src/components/ProviderRow.tsx:7` — text buttons have no hit area.**

`textButton` is bare 10px mono text, about 15px tall. The UI spec's one exception under 44px is
text buttons at `h-8`; only `rescan` (`Settings.tsx:10`) honours it. Change the constant to lead
with `inline-flex items-center h-8`, keeping the existing colour, transition, focus-visible and
disabled classes unchanged:

```
const textButton = 'inline-flex items-center h-8 font-mono text-[10px] text-ink-400 hover:text-ink-50 transition-colors focus-visible:text-ink-50 focus-visible:underline disabled:opacity-40';
```

Check the rows still read as one line after the change — the buttons sit in flex rows with `gap-2`,
so a taller button must not push the hint text or the model field out of alignment. If a row grows,
the fix is `items-center` on that row's container, not reverting the hit area.

**4. `web/src/components/ProviderRow.tsx:156` — dead hover token on the destructive confirm.**

The `remove the key` button carries an inline copy of the text-button classes plus
`hover:text-rust-300`. `index.css` defines only `rust-500` and `rust-400`, so that hover generates
no CSS and the button has no feedback. Replace the whole inline class string with the shared
`textButton` plus the destructive colours, so it gains the hit area from fix 3 at the same time:

```
className={`${textButton} text-rust-400 hover:text-rust-500`}
```

Do not add a `rust-300` token for one button.

**5. `web/src/pages/You.tsx:141` — Section 07 model input too narrow.**

`max-w-[320px]` gives a 318px box; a 59-character JetBrains Mono 14px id needs about 520px and
scrolls inside the field. The provider-row model inputs on `/settings` take the column width, which
is the behaviour this input should match. Drop `max-w-[320px]` from the class list so the input is
`${field} font-mono h-10`.

Leave `You.tsx:106` (the language input) at `max-w-[320px]` — a language name is short and that
field is not a gap.

**6. `web/src/pages/Lesson.tsx:122` — the tutor pill cuts the model id.**

`max-w-[28ch]` on 10px mono at `0.16em` tracking fits about 24 characters, so
`claude code · claude-opus-5-5` renders as `CLAUDE CODE · CLAUDE-…` — the pill cuts the one thing
it exists to show. Widen to `max-w-[40ch]`. Keep `truncate` and keep the full value in the `title`;
the pill is already `hidden md:inline-flex`, so desktop width is not a constraint.

**7. `server/src/codex.ts:166` — the model-refused hint names the retired mechanism.**

Replace the appended sentence so it points at the Settings row that now owns this:

```
message += ' Set the model on the Codex row in Settings (which model teaches), or leave it empty to use the Codex default.';
```

Keep the `friendly()` structure, the regex that triggers it and the login hint below it unchanged.
