<objective>
**As a** learner paying per token, **I want to** see what this lesson has cost me, where the lesson is, **so that** the price of learning is never a surprise I have to go looking for.

This delivers the learner-visible half of the cost slice: the two strings, the server-side sum that feeds both, and — because it is the single largest saving available and belongs with the number it reduces — the stable-prefix cache split that makes the figure smaller from the first lesson.

Purpose: make the cost of a lesson visible where the lesson is, in four honest words, from numbers the ledger actually holds.
Output: the stable/volatile instructions split with Anthropic cache control, the lesson-total field on `turn_end` and on both views, the cost segment in the header pill, the string on the Home row, and the suites.
</objective>

Split the system prompt into the half that never changes within a lesson and the half that does, and mark the first as cacheable.

**1. `server/src/driver.ts` — `TurnContext` grows two fields.** Add `instructionsStable: string` and `instructionsVolatile: string` beside the existing `instructions`, each with a one-line doc comment: the stable prefix is the rendered method text and the tool contract, held byte-stable across requests so a provider's prompt cache can hit it; the volatile tail is the material, the library, the learner profile and the lesson state, which change within a lesson. Keep `instructions` as the concatenation of the two, so `agent.ts`'s Claude driver and `codex.ts` read it exactly as they do today and neither is edited. A driver that wants the split reads the two fields; a driver that does not reads the one. Say that in the doc comment, because it is the reason the change is additive rather than a migration of three drivers.

**2. `server/src/agent.ts` — build both.** Where `instructions` is built, assign `const instructionsStable = systemPrompt(webSurfaceFor(tutor))` and `const instructionsVolatile = materialsSection(lessonId) + librarySection(lesson.learner_id, lesson.topic) + learnerProfile(lesson.learner_id, lessonId)`, then `const instructions = instructionsStable + instructionsVolatile`. The concatenation order is unchanged, so every existing driver receives a byte-identical string. Put all three on `ctx`.

**3. `server/src/drivers/adapters.ts` — the cache hook.** Add `cacheHook?: (content: string) => Record<string, unknown> | undefined` to the `Adapter` type, returning the `providerOptions` to attach to the **stable** system message. Every other row returns `undefined`: OpenAI and Gemini cache automatically and need only the prefix kept byte-stable, so there is nothing to attach — write that as a one-sentence comment on the `openai` and `gemini` rows so their empty hooks read as a decision rather than an omission. `openrouter` and `openai-compatible` also return `undefined`, because what they front is not knowable from here.

**4. `server/src/drivers/api.ts` — two system messages, stable first.** Change the `instructions` array to two entries: `{ role: 'system', content: ctx.instructionsStable, providerOptions: adapterFor(provider).cacheHook?.(ctx.instructionsStable) }` followed by `{ role: 'system', content: ctx.instructionsVolatile }`. Compute the lesson total once, on the server, and carry it everywhere it is read.

**1. `server/src/index.ts` — one helper.** Add `const lessonCost = (id: string) => costLabel(...costOfLesson(id))` built from `costOf(listUsage({ lesson: id }), priceTable())`, returning `string | null`. Put it beside `lessonView` with a one-line `/** … */`: the lesson's total as the learner reads it, or null when the lesson has no usage rows and therefore nothing to say. `listUsage({ lesson })` is an indexed query and `priceTable()` is cached for a second, so this is one indexed read on a hot view rather than a scan — the same rule `lessonView`'s own comment already states.

**2. `lessonView` carries it.** Add `cost: lessonCost(id)` to the returned object, beside the existing `tutor` field. This is what seeds the pill on first paint, exactly as `tutor` already seeds the provider and model.

**3. The lessons list carries it.** Add `cost: lessonCost(l.id)` to each row of `GET /api/lessons`. The route already does per-lesson work (`listNodes`), so this adds one indexed query per row and no new shape.

**4. `turn_end` carries it — `server/src/drivers/api.ts`.** Every `sink.endTurn` call in the api driver gains `lesson_cost: <the recomputed total>`, computed after the turn's usage rows are written so the number is settled rather than mid-flight. This is a **separate field beside** the existing per-turn `cost_usd`, not a replacement: `cost_usd` is one turn's figure and `lesson_cost` is the sum over the lesson's rows with its resolved label. Rendering the per-turn figure in a pill that promises a lesson total would read `about $0.03 estimated` on a lesson that has cost $0.40, which is a false number in a contract that argues for truthfulness everywhere else — put that sentence in the code comment beside the field.

Compute it with the same `lessonCost` path so A1 and A2 can never diverge; export the helper from a module both `index.ts` and the driver can import without a cycle (`cost.ts` is pure and `db.ts` holds `listUsage`, so a small exported function in the driver's own module reading those two is the simplest acyclic placement — do not import `index.ts`).

Guard the ordering: `sinkFor`'s `endTurn` is idempotent and the first call wins, so the lesson total must be attached to the **first** `endTurn` the driver makes on each path — the success branch, the stopping branch, the catch and the refusal — not only to the happy one. A path that forgets it leaves the browser with a stale figure after that kind of ending, which is exactly the silent case to avoid.

**5. `web/src/lib/types.ts` — the two shapes.** Add `cost: string | null` to the lesson-view type the `Lesson` page reads and to `LessonSummary`, each with a one-line doc comment naming it as the lesson's total as the learner reads it, already formatted server-side, or null when there is nothing to show. snake_case is reserved for wire fields that mirror the schema; `cost` is a computed string rather than a column, so it stays as written. The `turn_end` payload's `lesson_cost` keeps its snake_case because it rides the wire beside `cost_usd`.

**6. Do not touch `web/src/lib/useLesson.ts`.** The seeded value arrives through the lesson view the hook already threads through `init`, and the replacement arrives on `turn_end`, whose payload the reducer already receives. If the reducer genuinely cannot carry the value without a new branch, carry it in the page from the two sources it already has rather than adding an `EVENT_TYPES` entry or an `applyEvent` branch — both are refused by UI-SPEC Hard Prohibition 1, and a transient figure in the event log would also reach the SSE replay and the Obsidian mirror.

**7. `server/test/usage.test.ts` and `server/test/api-driver.test.ts`.** In `usage.test.ts`, add cases over the HTTP surface with no model: a lesson with no usage rows answers `cost: null` on both `GET /api/lessons/:id` and `GET /api/lessons`; a lesson with two rows of `cost_source: 'provider'` answers the summed `about $X.XX billed`; a lesson mixing `provider` and `table` answers `estimated`; a lesson whose rows are all `subscription` answers `not billed`; a lesson with one `unknown` row answers `not reported`.
