## Phase Goal

**As a** learner, **I want to** run Derive free and offline on a local model without the method silently degrading, prove any chosen model runs the method before I invest a session, and see what learning has cost across every provider, **so that** I am taught the Derive way on whatever model I have access to, with nothing lost between providers.

This plan delivers the first clause: a local model teaches, and the window is sized so the method is never silently truncated.

<objective>
Make the three local rows teach on the Phase 3 owned loop, and make the context estimate honest enough that the 16k floor means something.

Purpose: Ollama's default context window is 4,096 tokens and Derive's prompt floor is ~13,096 estimated tokens, so without an explicit `num_ctx` the method's gate, discipline and checks sections are truncated away and nothing errors. `headroomCheck` additionally cannot see the 3,349-token compact tool surface, so on a 16k window it is blind to a fifth of what it measures. Fixing the arithmetic is the precondition for D-04 and D-05 meaning anything.

Output: `ai-sdk-ollama@4.4.0` pinned; three adapter rows; `num_ctx` stored, bounded and editable; a tool-surface-and-window-aware `headroomCheck` with two distinct refusal sentences; compact tool descriptions and an outline-only material section on every local row; and the num_ctx refusal card with its `Settings` link.
</objective>

## Amendments to locked decisions (recorded with their rationale)

**A-01 — D-03's `num_ctx` default (owner decision, this planning session).** Research measured the offline-local system prompt at ~9,747 estimated tokens plus ~3,349 for the compact `api` tool surface — a ~13,096-token floor before a word of lesson. With `HEADROOM_FRACTION = 0.8`, a 16,384 window yields 13,107 usable tokens, i.e. ~11 tokens of slack, so D-03's locked default would refuse nearly every local lesson on sight. **16384 remains the refusal floor that D-04 checks a model's maximum window against, and the learner-editable `num_ctx` field's default becomes 32768.** D-03's own wording separates the floor from the default ("a fixed 16k floor … defaulting to 16384") and is marked reversible, so this is an amendment, not a break. **Floor and default are two distinct constants and must be named separately in the code.** The approved UI-SPEC refusal sentence ("raise the model's context window in Settings (num_ctx)") stays literally true, so `04-UI-SPEC.md` needs no edit for this amendment.

**A-02 — the local line's cost label (resolved conflict, locked artifact wins).** `04-RESEARCH.md` §Pattern 2 sketches `cost: () => ({ cost_usd: null, cost_source: 'unknown', searches: null })` for the local rows, and §Anti-Patterns says the Usage page then reads `not reported`. The **approved** `04-UI-SPEC.md` §Copywriting Contract gives the local line `… {tokens} tokens · not billed` and reserves `not reported` for "when the ledger has no counts". `cost.ts`'s locked vocabulary maps `subscription → not billed` and `unknown → not reported`. The UI-SPEC is the locked artifact, so the local rows report `cost_source: 'subscription'` when the request reported any token count and `'unknown'` when it reported none. `not reported` on a free turn that *did* report counts would claim Derive does not know what the turn cost, when it knows exactly: nothing. No fifth `cost_source` value is added — Phase 1 D-16 fixes the union at four.

## Flagged assumptions (spec-less edge probe — surfaced, not silently dropped)

**FA-01 (PROV-06).** The deterministic edge probe classified PROV-06 as `unclassified` and left it `unresolved`: it could not establish which data/behaviour-shape edges apply to "the context window sized so the method is never silently truncated". Per the spec-less fallback protocol an `unclassified` row is never auto-resolved with a backstop, so it is recorded here as an explicit planner assumption rather than authored into `must_haves.truths`. **The assumption:** the boundary cases that matter for PROV-06 are the three this plan tests from literals — an estimate exactly at `window × HEADROOM_FRACTION` (allowed), one token over (refused), and a provider the table carries no window for and no local row supplies one for (abstains, unchanged from Phase 3). If a verifier finds a fourth boundary this plan does not cover, that is a gap in this assumption, not in the requirement.
