## Phase Goal

**As a** learner, **I want to** run Derive free and offline on a local model without the method silently degrading, prove any chosen model runs the method before I invest a session, and see what learning has cost across every provider, **so that** I am taught the Derive way on whatever model I have access to, with nothing lost between providers.

This plan delivers the parity proof that keeps the first two clauses honest over time: a nightly replay that says, per provider, whether the method actually held.

<objective>
Build the one harness that replays a scripted lesson on every configured provider and reports whether the method held, and the narrow telemetry it reports alongside.

Purpose: nothing in this milestone has measured which models pass the understanding gate — STATE.md records that as an open concern, and the roadmap expects small local models to fail often. A harness that drives real models is the only thing that answers it, and a harness whose report is *complete* — every provider either tested or explicitly skipped with a reason — is the only kind a reader can trust.

Output: migration 9's append-only `tool_rejections` table and `recordToolRejection` at the one schema-rejection throw site; `scripts/conformance.mjs` producing a JSON report plus a Markdown summary and exiting non-zero on failure; `.github/workflows/conformance.yml` with a cron and a `workflow_dispatch`; the script registered in CI's parse loop and as a root `pnpm` entry.
</objective>

## Claude's Discretion resolved (CONTEXT.md left these to the planner)

**Where the rejection counter lives.** A counter column on `usage` would be per-request and would mean "this request's rejections", which is not what D-19 counts. A small **append-only table** — `turn_id`, `driver`, `model`, `tool`, `ts` — costs the same one migration and lets the report say both a rate and *which tool* a model fails on, which is far more diagnostic. `driver` is the column name because `recordUsage` already denormalises the turn's driver as the catalogue `ProviderId`, so the rate joins the ledger on a key that already exists.

**The report's shape and filename.** One JSON document per run plus one Markdown summary rendered from it. The JSON carries a run header (started, finished, the Derive version, the `think` setting the local rows ran under) and one row per provider+model with four verdicts — gate, pretest, cumulative, and the rejection rate — or a `skipped` status with its reason. Under `~/.derive/conformance/<ISO-8601 date>-<short run id>.json` and `.md` for the local run; into the `--out` directory for CI, which uploads it. Dated filenames rather than a single overwritten file, because the value of this report is the trend.

## Flagged assumptions (spec-less edge probe — surfaced, not silently dropped)

**FA-04 (PROV-13).** The deterministic edge probe classified PROV-13 as `unclassified` and left it `unresolved`: it could not establish which data-shape edges apply to "a harness replays a scripted lesson per provider and asserts the gate, pretest and cumulative quiz held". Per the spec-less fallback protocol an `unclassified` row is never auto-resolved with a backstop, so it is recorded here as an explicit planner assumption rather than authored into `must_haves.truths`. **The assumption:** the boundary cases that matter for PROV-13 are the four this plan covers — zero providers reachable (a complete report of all-skipped, exit 0), one provider failing a verdict (exit non-zero), a provider that is reachable but whose model never finishes a lesson (a timeout recorded as a failure, not a skip), and a key present but invalid (a failure with the provider's own sentence, not a skip). If a verifier finds a fifth, that is a gap in this assumption, not in the requirement.

## Research assumptions carried, not settled

- **A7** (`think: false` is accepted by every tool-capable Ollama model and does not break tool calling). This harness is the detector research names for it, which is why `think` is a harness variable here: a model that stops calling tools under `think: false` can be re-run at `'low'` and the difference recorded. Settling it needs a real Ollama server, which this machine does not have.
- **Which models pass the gate.** Deliberately unstated by research — this harness is the thing that answers it, and no ranking may be written into the repo ahead of a real run.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| harness → provider APIs | The script reads keys from the environment and makes real model requests. It runs **outside** the server's egress chokepoints, so it inherits neither `events.ts`'s redaction nor the route layer's `safeMessage` for free. |
| harness → CI artifact store | `actions/upload-artifact` publishes whatever the run wrote. On a public repository that is a public destination. |
| owned loop → `tool_rejections` | A new on-disk table written from one call site inside the turn loop. |
| GitHub repository secrets → workflow env | Four optional cloud keys reach the run's environment. |
