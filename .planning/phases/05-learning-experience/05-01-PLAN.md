<decisions_resolved_here>
These were recorded as the planner's call in CONTEXT.md §Claude's Discretion or surfaced as open by RESEARCH.md / PATTERNS.md. They are decided here so no executor has to invent them.

- **The `prompts` columns.** `id TEXT PRIMARY KEY`, `lesson_id TEXT NOT NULL`, `kind TEXT NOT NULL`, `payload TEXT NOT NULL`, `card TEXT`, `held INTEGER NOT NULL DEFAULT 0`, `settled INTEGER NOT NULL DEFAULT 0`, `answer TEXT`, `opened_at INTEGER NOT NULL`, `settled_at INTEGER`, plus `CREATE INDEX prompts_lesson ON prompts (lesson_id)`.
- **Lifecycle.** A settled prompt is **flagged**, not deleted: `settled = 1` with `answer` and `settled_at` written. The 409's shipped semantics are "a card is open *and unsettled*", and the terminal mirror's de-duplication needs the rendered card text after settling, so both need the row to outlive the answer. Settled rows are **swept at boot**, in the same block as the existing stale-turn close, because a settled row can no longer be answered and its card text is only useful inside a live terminal session.
- **`recentCards` moves into the row** (the `card` column holds `actions.renderCard(...)`'s output). PATTERNS.md open decision 3: if it does not move, a restart re-shows the model's prose copy of the open card in the mirrored terminal transcript. It moves, and the consequence of not moving is the reason.
- **The row is written through `redactDeep`** (`server/src/events.ts`), so the table inherits the same secret scrubbing the event log has. The answer key is not what `redactDeep` strips, so it survives — and the table is the only place it is allowed to live.
- **`busy` after a restart (RESEARCH Open Question 5, Pitfall 6).** `busy` keeps meaning "a turn is running". The `hasPending(id)` term is removed from its external branch; a card's liveness reaches the browser through `lessonView.pending` alone. Leaving `hasPending` inside `busy` once it reads a table would make every restarted companion lesson report `Teaching in your terminal` for a terminal that is no longer running.
- **No backfill.** An open prompt that existed before this table is already lost; that is the debt being paid, not data to recover.
</decisions_resolved_here>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| server → browser | Every field of `lessonView` and of the answer route's response crosses to a client the learner controls. The prompts row is the first durable copy of data that must not cross before the learner commits. |
| server → event log / Obsidian vault | `emit` persists and mirrors. A payload added here is permanent and leaves `~/.derive` when a vault dir is configured. |
| server → SQLite file | Migration 11 rewrites the learner's only record. |
| terminal (plugin / Codex MCP) → server | The external action route, whose one-card-open refusal this plan moves onto the table. |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-05-01 | Information Disclosure | the `prompts` row's `payload` (quiz `correct`/`explanation`, teach-back `rubric`) | high | mitigate | The row is read only by the server-side grading path through `promptPayload`/`settledAnswer`, whose doc lines say so. `lessonView` allow-lists `{id, kind, held}`. The restart gate in `api.test.ts` asserts the response body carries none of the three fields. |
| T-05-02 | Information Disclosure | a new event carrying the restored row | high | mitigate | Nothing new is emitted: the card payload the browser rehydrates from is the already-stored card event, which never held the key. `openPrompt`'s `emit` is unchanged. |

| T-05-04 | Elevation of Privilege | cross-learner read of a prompt row | medium | mitigate | Prompt reads are keyed by `lesson_id` and reached only through routes that already resolve the learner with `learnerOf(c)`; new routes inherit `guardLocal` and the install-token check from the `/api/*` middleware.
