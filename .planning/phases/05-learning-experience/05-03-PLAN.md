<objective>
A restored card is answerable, not just visible. The settle logic that grades a quiz is lifted out of the promise closure it lives in so both the live card and the restored card run the same grading, the answer route gains the branch that uses it, a fresh turn carries the result forward, and the learner sees `Grading your answer` in the gap. The reducer that renders all of it moves into a React-free module so a test can pin the event vocabulary.

Purpose: LEARN-12's complaint is not "the card disappeared" but "the question I was part-way through is gone". Restoring it read-only would lose most of that. And the status half of LEARN-11 is shipped except for the one line the learner actually waits through — the grading.

Output: `gradeQuiz` in `server/src/actions.ts` with the grading ephemeral beside it, the answer route's restore branch and fresh turn in `server/src/index.ts`, a `notice` item end to end, `web/src/lib/lessonReducer.ts`, and `server/test/reducer.test.ts`.
</objective>

<decisions_resolved_here>
- **The grading line's home.** One `emitEphemeral(lessonId, 'status', { text: 'Grading your answer' })` inside the extracted grading function, **immediately after** the `quiz_result` emit. CONTEXT.md D-16 says the status is emitted in two drivers; it is in fact three (`agent.ts`, `drivers/api.ts`, `codex.ts`) — and grading happens in `actions.ts`, not in any driver, so one call covers all three and none of them is touched. The ordering is load-bearing: the browser suppresses `status` while a card is open and unanswered, and that flag goes false the moment the result lands, so emitting before the verdict drops the line.
- **No `TOOL_LABELS` entry.** `TOOL_LABELS` is `TOOL_REGISTRY.filter(s => s.label)` — a per-tool vocabulary — and the wire-surface snapshot asserts the added label set is exactly the owned loop's two web tools. The string is emitted directly, as `Thinking` already is.
- **The suppression rule is verified, not rebuilt.** UI-SPEC's "suppression keys on 'a card is open and unanswered', not on 'a card exists'" is already true of the shipped `Lesson.tsx` gate. This plan asserts it and changes nothing there.
- **The resume-not-possible line is a `notice` event.** It is a durable fact about the lesson, not transient state, so the ephemeral channel is the wrong home and 01 D-14 does not apply. It is a new event type carried end to end in one task: the server `emit`, the `EVENT_TYPES` entry, the reducer branch, the `Item` union member and one render case. `server/src/export.ts` switches on type and has no case for it, so it stays out of the Obsidian mirror by construction — confirm that rather than add one.
- **Where the reducer lives.** `applyEvent`, `apply` and `EVENT_TYPES` are module-private in `useLesson.ts` today. They move to `web/src/lib/lessonReducer.ts` with type-only imports, re-exported into `useLesson.ts`, rather than being exported in place: the extracted module needs no `react` resolution, which is what makes `server/test/reducer.test.ts` cheap and what lets the test pin `EVENT_TYPES` against the server's emitted set.
</decisions_resolved_here>
