<decisions_resolved_here>
- **"Passed first try" (RESEARCH Open Question 2, operator decision).** `quiz_results` has no attempt ordinal and no `learner_id`. True retention is **the first `purpose='review'` row per `(lesson_id, node_id)` within the 90-day window**, and the denominator is the count of those first rows — which is also what the 10-row threshold is measured against. Learner scope is the `JOIN lessons l ON l.id = q.lesson_id WHERE l.learner_id = $l AND l.scratch = 0` the shipped aggregate already uses. A review session creates copies, so the same underlying node reviewed in three sessions yields three legitimate first tries; that is the intent. The definition goes into the `title` tooltip UI-SPEC specifies, so the learner can read it.
- **Null-stability locked nodes (PATTERNS open decision 5).** **Excluded** from both the numerator and the denominator of estimated knowledge. `retrievability()` returns a flat 1 when `stability` or `difficulty` is null, so counting such a node would silently over-report the one figure the panel exists to be honest about. `setNodeStatus` writes the FSRS fields on every path that reaches locked or shaky, so the case is rare; it is decided rather than inherited. When the exclusion leaves zero nodes, the block does not render, which is the same behaviour as having no locked nodes at all.
- **The thin-figure threshold (D-08 discretion).** 10, and only on true retention. Estimated knowledge is a computation over nodes rather than an estimate from a sample, so "not enough data" would be a false statement about it; desired retention is a constant; the forecast is a count of scheduled dates, and an empty fortnight is a true fact rendered as such.
- **The forecast's shape (D-06 discretion).** The 14-bar sparkline, which is UI-SPEC's recommended default and the shape fitted to the shipped 296px of aside content.
- **The stability ramp (D-09 discretion).** Logarithmic in stability-days over the 70–100% gold band, exactly as UI-SPEC fixes it: `t = clamp(log1p(stabilityDays) / log1p(180), 0, 1)`, fill `color-mix(in oklab, var(--color-gold-500) {70+30t}%, var(--color-ink-850))`, border against `--color-gold-400`/`--color-ink-700` at `{60+40t}%`, glow at `{55t}%`, ordinal alpha `0.75 - 0.20t`, text constant. The 70% floor is not an aesthetic choice: a ramp reaching to 20% crosses a band at 60–65% where neither the dark node text nor the light text clears 4.5:1 on the node label.
- **The ramp is inline `style`, not a class.** Tailwind v4 resolves arbitrary values at build time, so a per-node `color-mix()` cannot be a class string. It extends the node's existing `style` prop and replaces the shipped glow utility; the just-locked animation is **not** applied when a stability value is given, because its end state is the full halo and on the Atlas it would animate every node to a glow the ramp says it has not earned.
</decisions_resolved_here>
