<objective>
The learner drives the lesson from the keyboard and can strip the screen down to the one thing they are supposed to be thinking about. One scheme across all four cards, a `?` overlay that names only the keys that work right now, and a focus mode that hides the rail, the map and the header chrome while keeping the card, the prose above it and the composer.

Purpose: answering from the keyboard only helps if the learner knows the keys for the card in front of them, named at the moment they ask (the overlay's one-sentence learning reason); and one card plus the prose that explains it is the whole of what the learner is supposed to be thinking about (focus mode's). Both sentences are lifted from the UI contract rather than invented here, as the simplicity rule requires.

Output: one keydown scheme across `QuizCard`, `AskCard`, `ExplainCard` and `PlanCard`; `web/src/components/KeyHelp.tsx`; `web/src/lib/htmlAttr.ts`; one new CSS rule; and focus state with its grid swap, timeline filter, strip and Esc chain in `web/src/pages/Lesson.tsx`.
</objective>

<decisions_resolved_here>
- **Where the overlay is mounted (D-12 discretion).** One lesson-level overlay reading the active card, not a sibling of each card. The "no card open" row set exists in the contract — `f` and `Esc` with the heading dropped to `Keys` — and there is no card to be a sibling of in that state, so the lesson level is the only mount that can serve it.
- **Esc ordering against the shipped window listener (PATTERNS open decision 7).** The learner-switch menu is the only existing window-level Esc listener, and it is mounted in four page headers — not on the lesson page. So on the lesson page there is nothing to order against, and the three-step precedence chain is evaluated inside the lesson's single handler. Do not add the learner menu to the lesson header; keeping it off is also what keeps the shared-header extraction in `05-07` behaviour-neutral.
- **`?` inside the teach-back textarea.** The textarea is auto-focused and every keydown handler in the codebase bails inside a text field, so `?` will not open the overlay while a teach-back is being typed. That is correct — a question mark belongs in the prose — and it is **accepted rather than worked around**: the teach-back's hint row does not advertise `?`, and the overlay is reachable the moment focus leaves the field.
- **Focus mode needs three mechanisms, not one CSS rule.** The lesson body is a grid with declared 232px and 452px tracks, and `display: none` on a child does not collapse a declared track — the centre column would keep its width and sit offset. So: React state owns focus because the timeline collapse is a filter over items that carry no marker CSS could select on; the state writes the document-element attribute, which is what establishes the convention Phase 6 extends; and the grid columns swap by className. UI-SPEC's "exactly one new rule" is the budget for the *hide* rule, not the whole mechanism. Three mechanisms, named honestly.
- **The helper is worth its three lines.** Phase 5 is the first code in this repo to touch the document element, so this plan owns the convention. One `web/src/lib/htmlAttr.ts` gives Phase 6 a single seam for theme, accent, font and size rather than four scattered writes. It is a guarded const-arrow accessor in the shape of the shipped learner-key reader, and because focus is not persisted it has no storage half.
</decisions_resolved_here>
