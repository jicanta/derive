<objective>
The learner is told what to do next, and the count that tells them follows them everywhere. Home gains a three-row next-step block above the unchanged hero, and one shared header component carries a grey due pill on all six page headers plus Home's nav.

Purpose, lifted from the UI contract rather than invented, as the simplicity rule requires: retrieval beats re-reading, so the first thing a returning learner reads is the review that is due, not a blank topic box — and a review the learner cannot see is a review they do not do, so the count follows them and the forgetting curve is never out of sight.

</objective>

<decisions_resolved_here>
- **The learner-switch menu stays an optional child (RESEARCH Open Question 4, operator decision).** It is in four of the six headers today and absent from the lesson and the atlas. The shared component takes it as an optional child and it is **not** added to those two: a new control on two more surfaces would owe its own one-sentence learning reason, and this phase does not need to spend one. The extraction is behaviour-neutral apart from the due pill and the title's width floor.
- **The shared header does not absorb the lesson's extras (D-03 discretion).** The phase indicator, the locked count, voice, export and the live dot stay page-specific children. Five of the six pages have none of them, and absorbing them would turn a shared component into a lesson component.
- **Where the pill goes in the lesson header.** The lesson header has **two** right-side groups, not one: the first is wide-screen-only and holds the phase indicator; the second is always visible and holds the locked count, voice, export and the live dot. The pill goes in the **second**, because "visible at every width" has no exception to make — it cannot sit in a single right slot that does not exist there. Order within that group: locked count, pill, voice, export, live dot.
- **The pill is grey, and the title gets a width floor.** Both are in the UI contract and both have reasons worth repeating here: grey because a pill that reads as a nudge on six pages is a nudge nobody can dismiss, and the reminder requirement is deferred; the floor because the open review finding is that this exact header already starves its own topic, and the shared component is the only place that rule needs to exist rather than being repeated on six pages at once.
- **The accessible name on the back link** is the UI checker's non-blocking flag, landed here: worded from where the link goes, so the usage page's back link reads correctly rather than saying "all lessons" while going to settings.
- **The next-step block is its own component (D-01 discretion).** `NextStep.tsx`, so Home does not grow another responsibility, and because the UI contract already locks its look either way.
- **One fetch, two decisions.** The lesson page's single stats call serves the due pill and supplies `prefs.language` for voice, which `05-02` shipped a seam for. Two fetches for one payload is the thing to avoid here.
</decisions_resolved_here>
