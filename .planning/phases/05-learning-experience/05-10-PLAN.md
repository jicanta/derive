<objective>
Close G-05-1b: a turn that starts without the earlier conversation — after a provider change (03 D-04) or any lost session — currently receives nothing about the lesson it is in, because the learner profile excludes the current lesson by design, no driver seeds a fresh session from the lesson's rows, and the system prompt's volatile half is materials, library and profile only. The tutor then says there is "a fresh graph to build" and probes another topic. This plan adds the one small helper the diagnosis justifies: `lessonBrief(lessonId)` — topic, goal, phase, one line per node, this lesson's unresolved misconceptions — prepended to the turn prompt in `runTurn` the way pending notices already are, only when the turn is fresh and a prior turn exists; it shares the fresh-turn predicate with the restored-answer notice, and makes the three sentences that already promised this context true.

Purpose: D-26 says the learner never loses a graded answer, and 03 D-04 says a provider change drops the conversation; between them a fresh turn must be able to carry on from the lesson's own record. Without the brief the method's graph, gate and review loop vanish at exactly the moment the project's core value — nothing lost between providers — is tested.
Output: `lessonBrief` in `server/src/db.ts`; the fold and the shared predicate in `server/src/agent.ts`; `server/src/index.ts` importing it and its closing sentence corrected; `server/src/driver.ts` docs corrected; the api-driver suite extended.
</objective>
