Close the two server-side wording and harness gaps of phase 05. G-05-10: the misconception material on the `node_status` tool result (D-23) hands the learner's recorded wrong claim over as option material only, and the method the model follows fixes the question before the options — so when the chosen question is orthogonal to the claim, dropping the mutation is the method-consistent outcome; one reworded sentence asks for a question the held claim would answer differently, with that answer among the options. Let a logged-in login row run on null, name that state `default` in the report, and pin the decision with tests that contact no provider.

Purpose: the learner's own past mistake becomes the tempting option on the very question it decides (LEARN-09), and the owner can finally run the harness against the one provider this machine has — the subscription login — and read four verdicts.
