Start a Derive lesson on: $ARGUMENTS

1. Load the `teach` skill from the derive plugin and follow it exactly. It is the only teaching method you use.
2. Call the derive `start_lesson` tool with the topic. If the argument names files, folders or URLs (course slides, a PDF, lecture notes: .pdf, .pptx, .docx, .md, .txt; a repository folder; a GitHub URL), pass them as `files`; the tool uploads or imports them and returns a brief of the material (its outline, or its full text when short) with instructions on using it. If the argument contains `--terminal` or the learner asks to answer here, pass `answer_in: "terminal"`; if it contains `--learner <name>`, pass `learner`. Strip those flags from the topic. `start_lesson` also opens the companion page in the browser and returns what is already known about this learner. Read both before probing: follow the learner's own preferences (language, style, pace, background, examples) in how you deliver, and if they tell you mid-lesson how they want to be taught, save it with `set_preferences`; build on locked nodes, re-derive shaky ones, watch for listed misconceptions, and when there is material, read the relevant pages or files with `read_material` before you plan so the plan covers what the course covers, in its notation. If the learner mentions files later, `attach_material` adds them mid-lesson. `start_lesson` also returns `warmup` when nodes from earlier lessons are due: do that first, exactly as it says (one fresh `quiz` per node with `purpose: "review"` and the given id, lock or mark shaky, no teaching), then the probe. It also returns `library` when the learner keeps one: the entries of their library relevant to the topic and the rules for using it (`search_library` before you plan, `read_resource` to borrow framing and examples, `suggest_resource` to point them at the right chapter or timestamp when a node locks, `add_resource` to save a source you found on the web, sparingly).
3. Run the lesson in the terminal: your prose here, every graded question through `quiz`, every open question through `ask`, the plan through `set_plan`, node states through `node_status`. Where the learner answers depends on `answer_in`, which `start_lesson` returns:
   - **browser**: each of those tools blocks until the learner answers in the browser and returns their answer.
   - **terminal**: each of those tools returns the card as text at once. Show it verbatim as your message, then end your turn. The learner's next message is their reply: pass it, verbatim, to `answer` before anything else; it returns the graded result. Never answer for them, never continue past an open card, never reveal an explanation before `answer` has returned. If they answered in the browser meanwhile, `answer` returns that.

If `start_lesson` fails because the server is not running, tell the learner to run `pnpm start` (or `pnpm dev`) in the derive repo and stop.
