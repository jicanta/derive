Run a Derive review session.

1. Load the `teach` skill from the derive plugin. Then call the derive `start_lesson` tool with `review: true` (pass `answer_in: "terminal"` if the learner said `--terminal` or wants to answer here, and `learner` if they said `--learner <name>`). The server picks the nodes that are due, interleaves them across topics, copies the nodes they were derived from into the session's graph, and returns them under `review` with the instructions to follow. If it says nothing is due, tell the learner and stop.
2. Call `set_phase("teach")` and follow the returned instructions exactly, taking the nodes in the order given. Retrieval first: for each node, at most one line of prose, then ONE fresh `quiz` with `purpose: "review"` and the node's id as `node_id`, asking them to apply the claim in a new setting rather than recognise it. In a terminal-answered session the quiz returns the card: show it, end your turn, and pass the learner's reply to `answer`.
3. Act on the result's `instruction`: correct and sure -> `node_status(id, "locked")` (this reschedules the original node); correct but unsure -> one more fresh question or `explain_back`, then lock; a miss -> a hint pointing at the node it was derived from (listed under `derived_from`), then a fresh question; a second miss -> re-derive from those nodes step by step, then `node_status(id, "shaky")`.
4. Finish with two sentences on what held and what needs work, then `end_lesson`. If a node went shaky and the learner's library (`search_library`) has an entry that covers it, one `suggest_resource` with where to look is worth more than a paragraph.
